## 完成接入所需的信息与顺序

1. 收集最多五位指定成员的邮箱，必须包含管理员本人。邮箱名单只放在本机忽略目录或 Cloudflare，不提交公开 Git 仓库。
2. 在 Cloudflare Zero Trust Free 建立素材库专用应用，目标使用 `worker` 与上述唯一 Worker ID，覆盖该 Worker 的所有入口，禁止 `all_workers`／`all_preview_workers`。现有版本预览 URL 已关闭，保持关闭。
3. 允许策略只包含指定邮箱，认证使用 One-time PIN，素材库应用和允许策略的会话使用平台支持的最长值（目前一个月，接入时再次确认），不改账号级全局会话。不得用 Everyone、邮箱域名通配或 Bypass 作放行策略；不新增付费订阅。若首次 Zero Trust 设置要求接受条款，交给用户本人完成。
4. 让管理员完成一次邮箱入口验证，并给本地成员账号管理程序接入官方 cloudflared 的相同邮箱验证流程。不得为方便 CMD 管理而给公开 API 添加绕过 Access 的入口；管理员令牌与访问令牌不得进入网页配置或 Git。
5. 实测匿名访问正式入口、API、后台根路径被 Access 在边缘拦截，授权邮箱可以打开 `/studio/` 并使用五个成员账号；再次检查上传、下载与退出。检查应急关闭、恢复以及插件配置保持不变。
6. 验收后再把 GitHub Pages 首页改成新入口的跳转页，保留完整网站源码与同步流程。之后每次修改网站都需要重新打包并部署该素材库 Worker 的静态文件，不能只推送 GitHub。

## 额度与局限

Access 的边缘拒绝发生在 Worker 执行前，是阻止陌生请求刷 Workers 动态额度的关键。**后端 HTTP 429 本身已执行 Worker，仍计入额度**；不能把后台限流说成硬性保障每日总次数不会超过十万。已获授权的成员持续恶意请求、已泄露的访问会话以及其他 Worker 的使用仍需由账号总用量监测判断。同一账号的免费额度仍与插件共享，没有为素材库划分独立免费额度。

D1 安全计数会消耗 D1 读写配额，不新增数据库或付费服务。静态资源请求不运行 Worker 时不计动态请求次数，目录、身份、整理、上传地址签发仍计动态请求。没有新增后台轮询。
